# Project Lead

[English](README.md) | 简体中文

一个 Codex 项目管理 Skill：日常执行优先考虑 GPT-6 Sol、GPT-6 Luna，确有深度需求时直接选择 GPT-6 Astra，不强制固定模型或档位。派发前用表格说明完整模型代际、任务、档位、速度和理由，只告知、不增加审批；子任务可按需沟通，只有重大或安全风险才独立审查。总控保持负责人清晰并验证可用结果，减少无效审查循环。

## Project Lead 1.0

Project Lead 1.0 把一个能干活的 Codex 对话变成**真实的项目控制层**：让负责人可见、按当前目标路由执行、只在真实风险下审查，并把结果讲清楚，而不是不断堆叠任务和过程日志。

它只遵守一个原则：**根据真实风险使用最少但足够的流程**。总控负责范围、任务归属、阻塞、验收和汇报；执行线程负责项目产物和实质执行。普通任务由一个明确 owner 快速推进，高风险任务保留独立门禁。

Project Lead 是决策与协调 Skill，不会假装替代 Codex App 缺失的能力。接口没有注册、速度字段不存在、或总控已空闲时，**没有可用的提示词补救办法**可以凭空修好它们；下文会明确区分已验证的行为与这些平台边界。

## Project Lead 能力一览

| 能力 | 用户能看到的结果 |
| --- | --- |
| 可见负责人 | 实施、审查和长验证都进入有标题、侧边栏可见的任务；同一目标复用同一个执行线程。 |
| 审批边界 | 范围内常规工作由总控自行批准；只有真实权限或产品策略决定才询问用户。 |
| 目标级模型路由 | 够用时优先 GPT-6 Sol/GPT-6 Luna，需要时直接选 GPT-6 Astra；模型和档位都按任务判断，不强制、不继承。 |
| 派发透明 | 每次派发或实质性跟进前，以表格展示任务、任务线程、模型、推理档、速度档和选择理由；只告知，不等待批准。 |
| 子任务沟通 | 同项目任务在工具可用时可直接澄清真实依赖；不能互相改变任务范围、模型或验收结论。 |
| 额度回退 | 任何模型因额度或容量失败后，先结束旧尝试并核对成果，再选择至多一个平台支持、已授权且适合剩余工作的回退模型；重新选择档位，不在模型间来回跳。 |
| 按风险审查 | 普通任务没有额外审查阶段；只有重大或安全风险才触发有上限的独立审查。 |
| 能力发现 | 可自动选择一个已安装配套 Skill；缺失能力只搜索和推荐，安装仍需用户同意。 |
| 完成回传 | 客户端提供 `wait_threads` 时即时回传终态；接口不可用时如实降级，绝不假装后台监控。 |
| 上下文换线 | 总控、执行和审查线程的上下文过长时，在可靠性下降前交接给新的可见任务。 |

## 总控审批权与执行边界

在已经批准的项目目标内，总控自行批准正常派发、本地可逆准备、针对性检查、规定的独立审查和范围内返修。Elevated 审查本身不需要用户批准：内容风险决定审查强度，拟执行动作和缺少的权限才决定是否询问用户。只有真实的产品或安全策略分叉、新权限或密钥、不可逆或破坏性操作、外部副作用、付费、部署或发布才交给用户；真正只能由用户点击的平台批准卡仍会立即转达。

总控只承担接管、路由、无代码的跨模块决策、验收、汇报和快速只读抽查。计划、设计、源码、测试、复杂调试和长验证都属于执行任务，不能拆成多个“小步骤”留在总控。旧批准阻塞绑定一个具体目标、候选、动作和权限缺口；身份或需求变化后立即失效。

Elevated 风险只会提高独立审查强度，不会自动创建一轮总体架构。只有出现真实的跨客户端或跨服务边界、未解决的共享契约或重大返工风险，才进入总体架构阶段。

## 可见的执行任务

正式实施、独立审查和长验证必须通过 `create_thread` 创建为有明确标题、侧边栏可见的独立 Codex 任务，不能用内部子智能体替代。这样用户可以在左侧找到任务、查看完整过程，并处理相应的批准卡。若 `create_thread` 不可用，Project Lead 报告 `blocked_on_visibility`，不会把工作说成已派发。内部子智能体只可做短时只读辅助，不能拥有可变范围、等待用户批准、审查、验收或结项正式任务。

## 长任务上下文换线

总控、执行或审查任务达到已观察到 80,000 Token 的软阈值后，只完成当前有边界的步骤，不再接收下一阶段。达到 100,000 Token 或 5 MB 任务历史时，必须在下一阶段前退休；分页、压缩或历史截断也属于硬触发。总控换线不会重启仍在运行的执行任务。

Token 阈值指当前上下文输入量，不是所有回合累计计费 Token。这是 Project Lead 的保守交接阈值，不是模型的官方上下文上限。总控继任者保留用户选择的 Astra 路由和现有子任务负责人；模型窗口增大，不足以证明客户端回传问题已经解决。

Project Lead 会建立新的有标题、侧边栏可见任务，只传递包含剩余目标、负责人和可写范围、真实来源路径或 ID、已接受证据、阻塞、下一项检查和路由的精简交接包。它不会复制完整旧对话；新任务修改前重新核对现场，旧任务标记退休并记录继任者，不会产生两个并发修改负责人。无法创建可见继任任务时报告 `blocked_on_visibility`，不会继续复用超长任务。

完成回传为空/null 时，先恢复原任务的终态记录，再考虑任何重跑。它属于传输问题，不代表执行失败；Project Lead 不会为了补一段文字重新执行或重新审查，无法恢复时报告 `blocked_on_relay`。

## 自动选择与搜索 Skill

**你只需要描述目标，不需要记住 Skill 名称。** 在接收项目以及进入每个新阶段时，Project Lead 会：

- 有明确触发条件时，自动选择并调用最多一个已经安装的相关 Skill；
- 普通且范围明确的工作选择 `none`，不会为了“保险”堆叠一批 Skill；
- 只有确实缺少必要的专业验收能力时，才进行一次保护隐私的只读公开搜索；
- 最多推荐三个候选，说明对当前项目的作用和风险，并且任何安装前都会先征得你的同意。

例如，涉及 Apple 手势和动效时可以选择 `apple-design`，遇到真实模块边界问题时可以选择 `codebase-design`，验证可运行的网页流程时可以选择 `webapp-testing`。搜索到的候选说明始终按不可信信息处理，不会在搜索阶段执行或自动安装。

## 子任务之间直接沟通

总控在有依赖关系的任务说明里附上同项目相关任务的真实 ID、职责范围和沟通边界。执行任务在接口可用时可以直接问一个具体问题、交换已有证据，不必让用户逐条转达；不能互相派新活、换模型、修改对方负责的文件或批准完成。已完成任务优先读取结果，不为查状态唤醒。禁止广播、收到回复后反复致谢、循环询问状态；有分歧只向总控升级一次。发消息可能唤醒对方并消耗额度。接口缺失时由总控转达，Skill 不能提供平台不存在的能力。

## 自动选择执行模型

本版重点使用 **GPT-6 Sol（`gpt-6-sol`）、GPT-6 Luna（`gpt-6-luna`）、GPT-6 Astra（`gpt-6-astra`）**。规则、派发表格和实际参数必须写完整代际，不能凭“Sol/Luna”简称推断版本，也不能静默替换代际。用户明确限制仍然有效；总控的档位及 Fast 设置不会传给子任务。

| 角色 | 模型规则 |
| --- | --- |
| 总控 | 保留用户选择的模型和档位。 |
| 必要独立审查 | 独立且已授权的 GPT-6 Sol 或 GPT-6 Astra；独立性来自不同执行者和证据，不要求必须换模型名称。 |
| 日常实施 | GPT-6 Luna 可做明确的小修改、测试、小功能和文档；GPT-6 Sol 可做常规开发、调试和多条件任务。两者都可以写代码。 |
| 复杂实施 | 深度诊断、未决架构或重要边界确有需要时直接选 GPT-6 Astra，不要求先让便宜模型试错。 |
| 旧代际 | GPT-5.6 Luna（`gpt-5.6-luna`）仍一律只读；GPT-5.6 Sol（`gpt-5.6-sol`）仍用于总控/审查。这些限制不套用到 GPT-6。 |
| 普通任务 | 执行者检查、总控验收，不设常规独立审查阶段。 |
| 旧版只读信息助手 | 仅限 GPT-5.6 Luna（`gpt-5.6-luna`）。GPT-6 Luna 是执行候选，不再分配这个助手角色。 |

选择前核对目标主机接口实际支持的完整型号和档位，不编造别名，不静默更换代际，不把“请求选择”说成“实际运行已验证”。[完整模型规则与证据限制](skills/project-lead/references/model-routing.md)。

用户每个项目只授权一次自动路由。每个新目标都会根据当前边界明确的子任务本身——动作、不确定性、耦合、后果、检查，以及派发工具实际支持的组合——同时选择模型和推理档位，绝不继承上一个目标的路由，也不会继承父项目、审查通道或上一个任务的档位。

- 需求明确、范围小、检查确定时可以考虑 low；多个条件互相影响、存在不明显边界时可以考虑 medium，不强制从某档起步。
- 更高档位必须有当前任务的具体理由。缺证据先查证，工具或环境错误先查原因，不自动升档。高档不保证正确，低档也不保证总成本更低。
- GPT-6 Luna 可以开发简单任务；只有 GPT-5.6 Luna 保留模型级只读限制。所有模型仍须遵守用户明确的任务边界。
- 独立审查只在具体重大或安全风险、或用户明确要求时触发。执行模型改变不会自动增加审查，也不会重新打开已经通过的审查。
- 执行候选仅限已授权、当前工具目录支持的 GPT-6 Sol、GPT-6 Luna 和 GPT-6 Astra。够用时优先 GPT-6 Sol/GPT-6 Luna，但不是硬性规定；任务确有需要时可以直接选择 GPT-6 Astra。不固定模型或档位。

上述是判断示例，不是强制最低档。审查档位单独选择，高风险标签不等于必须 xhigh；max/ultra 按实际接口解释，名称本身不授予并行助手权限。三道本地测试支持更多日常工作交给 GPT-6 Sol/GPT-6 Luna，但不是通用能力排名：额外租户切换测试仍发现漏项。公开 API/credits 单价不等于订阅额度比例，不能承诺降档或少用 token 必定省钱；不为统计节省情况重复做任务或增加常规审查。

选择 xhigh、Max 或 Ultra 前，总控会做一次静默判断：说明低一档最可能造成的具体失败风险。这个判断不会调用工具、新建任务、调用 Luna 或并行比较模型。文件多、上下文长、名称带“架构/安全”或以前失败过，都不能单独作为升档理由；根因和范围收窄后，下一次跟进应重新判断并在风险消失时降档。

每次派发前会告知任务、模型、档位和实际速度，并附上一句当前任务的选择理由；以两列 Markdown 表格展示执行任务、任务线程、模型、推理档、速度档和选择理由，不放在代码块里；同时派发多个任务时可合并成每个任务一行。不会等待批准，这是通知而不是请示。速度默认显示普通，只有用户已明确要求该目标使用 Fast 时才显示 Fast。如果额度回退或实际路由核验改变了选择，总控会先发更正通知再重新派发。

通过 `create_thread` 创建的正式执行任务从空白上下文开始。内部辅助和审查任务只获得无历史或有限历史，不能继承完整历史。如果派发工具能原子返回实际路由，就在开工前核对。普通任务创建成功后不再额外执行握手任务，前提是已明确传入平台支持的模型和档位且没有错配证据；高风险审查也适用。请求被接受与实际路由已核验分开记录，不用模型自述冒充验证。出现真实错配时先恢复正确路由，无法解决才报告 `blocked_on_routing`。

没有模型和档位字段的普通跟进不能原地切换；当前回合结束或中止后，再把同一逻辑范围交接给唯一一个路由正确的任务，绝不产生两个并发负责人。容量回退时，只等待同一目标或逻辑范围里的失败尝试结束；无关范围仍可并行推进。

如果原任务已空闲，且 `send_message_to_thread` 支持 `model` 与 `thinking`，就显式传入下一回合的模型和档位，复用原线程。执行线程和 Luna 都适用，无需仅为换档新建任务；不能修改正在运行的回合。

任何模型因用量、额度或容量限制而失败后，总控先确认原尝试已经结束，核对真实工作区里的已完成和部分成果，再从当前工具支持、已授权且适合剩余工作和角色的模型中选择一次临时回退。执行回退同样仅限 GPT-6 Sol、GPT-6 Luna 和 GPT-6 Astra，沿用按任务判断的选型偏好；新模型的档位根据剩余工作重新选择，不继承，也不自动提高。回退只对当前目标生效，不成为项目默认模型。没有合适候选，或本目标的回退尝试再次因额度或容量失败时，报告 `blocked_on_capacity`，不在模型之间来回跳。

## 下发任务默认使用普通速度

Fast 速度不等于低风险通道。总控本身可以保留用户当前设置的速度，但该设置不会授权给下发任务。每个新执行任务默认使用 Standard/普通速度，后续继续执行也保持普通速度；Project Lead 不会主动询问是否使用 Fast。只有用户主动明确要求当前子任务使用 Fast 时才启用，目标结束后立即失效。

派发接口没有速度字段时，不传入任何 Fast/priority 覆盖，直接使用平台的 Standard/普通默认值；缺少字段不会阻塞普通派发。如果之后出现子任务意外使用 Fast/priority 的真实证据，总控停止继续派发并立即说明。

速度无法回读时，通知写“平台默认（未回读）”，不把请求使用默认速度说成已经核实实际速度。

## GPT-5.6 Luna 只读信息助理

当大量或重复证据会明显占用总控上下文或额度时，可使用一个项目级 `gpt-5.6-luna` 只读助手。不可用就省略这个可选助手，不改派 GPT-6 Luna 担任。档位按证据复杂度选择，不固定 medium；只汇总带来源的报告和证据，不为普通状态更新额外调用。

这个旧版助手不能写代码、调度、审查或验收。GPT-6 Luna 用于执行，包括简单编码任务，在用户已授权范围内完成并报告结果；最终验收仍归总控。

## 事件驱动的完成回传

执行任务接受派发后，Project Lead 使用 `wait_threads` 保持总控回合，直到所有承诺等待的任务完成或需要处理。等待超时只会续接事件等待，不会触发轮询、重复读取或调用 Luna。一个任务结束时，总控先在过程中转达，再继续等待其他任务。

只有需要用户输入、用户明确停止等待或事件等待工具不可用时，总控才能提前结束。`wait_threads` 不可用时，总控只发出一次简短的降级说明：当前客户端无法自动回传完成事件，但已接受或运行中的任务没有因此改变。它不会重试接口、轮询、调用 Luna，也不会在同一总控回合反复提示；会在报告当前状态后结束。之后用户只要说“继续”或“跟进”，总控才进行一次新的读取。Luna 和 30 分钟规则都不能唤醒空闲总控。

## 风险分级审查

| 模式 | 适用情况 | 审查方式 |
| --- | --- | --- |
| 低风险通道——默认 | 文案、样式、测试、本地修复、小型可逆行为、既定接口下的孤立改动 | 不创建独立审查线程。总控核对真实 diff、工作区和针对性检查后直接验收。 |
| 高风险模式 | 可能造成资金错误、鉴权失效、密钥或隐私泄露、数据丢失或重大线上故障的实际改动，包括不安全的迁移和重要发布 | 稳定候选交给独立且已授权的 Astra/Sol，按内容选择档位。不能只因模块名字、文件数量或普通集成就升级。 |

同一目标在两次退回后不再重复相同的增量审查循环。必要审查复用同一候选的有效证据，一次提出有复现依据及实际影响的严重问题；轻微问题不触发返工复审。第二次退回后，总控派发一次根因修复和一次最终独立收口；不发起第四轮，仍有未解决严重问题就保持 `RETURN` / `blocked_on_quality`。

## 工作方式

1. 检查当前代码仓库和活跃任务。
2. 区分当前可用结果与以后可做的优化。
3. 每个可变范围只保留一个负责人，修复继续复用原任务。
4. 根据实际失败后果选择普通验收或高风险审查。
5. 只运行改动范围和项目规则真正要求的检查。
6. 用用户能看懂的语言汇报进度。

项目产物、主要实现、复杂调试和长时间验证都留在执行线程。

信息不足不会自动升级成总体架构任务或用户问题。总控先自行检查或派发取证，只有用户独占的产品事实或新权限才询问。只有真实的跨客户端/服务边界、未解决的共享契约或重大返工风险，才进入总体架构阶段。

## 简明反馈

默认只给用户四行：

```text
已完成：<用户能理解的结果>
当前结果：<能否使用或验证>
阻塞：无 | <需要用户处理的唯一事项>
下一步：<一个最有价值的动作>
```

除派发前必须显示的模型与档位通知外，Base/Head、SHA、审查编号和内部台账默认隐藏；只有用户主动询问，或它们能解释真实阻塞时才展示。

被总控验收的执行任务会收到一次结项回执：

```text
【总控结项回执｜非新任务，无需回复】
当前任务：<已接受的任务目标>
当前状态：已完成，等待下一步指令。
```

回执按任务和已接受候选去重。消息可能唤醒线程，但不新增工作或待等待目标；不会再针对确认回执发送新的回执。

## 协调与批准提醒

- 一个工作区或可变范围只允许一个负责人。
- 独立模块可以并行，共享文件、迁移和共享契约必须串行。
- 派发成功不等于任务完成；总控必须读取终态报告并核验证据。
- 只有真正越过审批边界的请求才通知用户，并说明任务、动作、风险和操作位置。总控不会把普通审查或本地工作包装成文字审批，也不会猜测平台批准卡正文。
- 连续 30 分钟没有实质进展时，只允许一次只读快照和一次 Luna 状态询问；不创建 heartbeat、cron 或轮询。

## 配套 Skill 与能力发现

每个阶段最多选择一个真正需要的设计或探索类 Skill；普通工作不额外启用任何 Skill。

缺失能力查找已经内置，而且只读，不调用 `find-skills`。只有确实缺少专业验收方法时才搜索；搜索词会脱敏，候选内容按不可信信息处理，最多推荐三个。发现过程不会自动安装，也不会阻塞无关工作。

候选绑定、原子安装、失败回滚和崩溃恢复细节放在[安装安全参考](skills/project-lead/references/skill-installation-safety.md)中，只有用户批准精确候选后才读取。这样普通项目不会承受安装协议的上下文成本，同时保留原有安全边界。
