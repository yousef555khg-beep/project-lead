# Project Lead

[English](README.md) | 简体中文

一个用于协调多模块项目、自动判断 Spark 或 Terra 执行模型、自动选择合适配套 Skill，并避免普通任务陷入无效审查循环的 Codex Skill。

## 核心变化

Project Lead 现在只遵守一个原则：**根据真实风险使用最少但足够的流程**。项目进度看的是用户能否得到可用结果，而不是创建了多少任务、做了多少轮审查或输出了多长的技术报告。

总控仍负责范围、任务归属、阻塞、验收和汇报；执行线程负责主要实现。小任务可以快速完成，高风险任务仍保留独立门禁。

## 自动选择与搜索 Skill

**你只需要描述目标，不需要记住 Skill 名称。** 在接收项目以及进入每个新阶段时，Project Lead 会：

- 有明确触发条件时，自动选择并调用最多一个已经安装的相关 Skill；
- 普通且范围明确的工作选择 `none`，不会为了“保险”堆叠一批 Skill；
- 只有确实缺少必要的专业验收能力时，才进行一次保护隐私的只读公开搜索；
- 最多推荐三个候选，说明对当前项目的作用和风险，并且任何安装前都会先征得你的同意。

例如，涉及 Apple 手势和动效时可以选择 `apple-design`，遇到真实模块边界问题时可以选择 `codebase-design`，验证可运行的网页流程时可以选择 `webapp-testing`。搜索到的候选说明始终按不可信信息处理，不会在搜索阶段执行或自动安装。

## 自动选择执行模型

用户每个项目只授权一次自动路由；Project Lead 不会在每次切换时重复询问。每个新目标都会重新判断当前范围、证据和风险，绝不继承上一个目标的模型。

- 只有目标范围、既定模式、可逆性和针对性验证都明确的快速任务，才允许使用 Spark。
- 任一 Spark 条件不满足或无法确认，以及标准或高风险实现、复杂调试、跨模块影响和范围扩大时，都保守选择 Terra。
- Spark 升级到 Terra 时复用同一个任务，在下一轮明确指定 Terra；不会在回复生成到一半时强行换模，也不会把中断的任务说成已完成。
- 执行模型不会削弱独立审查：标准审查仍使用 Terra，高风险审查仍使用 Sol，Spark 不得审查自己的实现。

任务是否适合 Spark 与 Spark 当前是否可用会分别判断。如果派发前已知研究预览额度用完或模型不可用，已授权的总控会为当前目标明确回退到 Terra。如果 Spark 已经被接受、运行或排队，总控不会并发启动 Terra；只有确认 Spark 被拒绝、中止或结束后才继续，并在下一个目标重新检查 Spark。

## 风险分级审查

| 模式 | 适用情况 | 审查方式 |
| --- | --- | --- |
| 快速模式——默认 | 文案、样式、测试、本地修复、小型可逆行为、既定接口下的孤立改动 | 不创建独立审查线程。总控核对真实 diff、工作区和针对性检查后直接验收。 |
| 标准模式 | 单一模块内有实际逻辑的多文件改动，或既定契约下的有限集成 | 完整候选稳定后集中做一次 `gpt-5.6-terra high` 审查；最多再做一次增量修复复审。Minor 不触发退回。 |
| 高风险模式 | 鉴权、授权、密钥、隐私或受监管个人数据、加密协议或安全合规、支付、破坏性操作、数据丢失或所有权、迁移、并发与恢复、共享契约、跨模块集成、部署、发布或总体架构 | 一个稳定候选使用独立 `gpt-5.6-sol xhigh` 审查。确实不可逆的前置架构决定可以在实现前单独审查一次。 |

同一目标绝不自动发起第三轮审查。连续两次退回后，总控必须停止循环，用通俗语言告诉用户根因和可选方案。

## 工作方式

1. 检查当前代码仓库和活跃任务。
2. 区分当前可用结果与以后可做的优化。
3. 每个可变范围只保留一个负责人，修复继续复用原任务。
4. 根据具体风险选择快速、标准或高风险模式。
5. 只运行改动范围和项目规则真正要求的检查。
6. 用用户能看懂的语言汇报进度。

没有执行线程占用相关文件时，总控可以直接处理简短、孤立、可逆且能立即验证的小改动。委派的快速任务只有在全部白名单条件成立时才使用 Spark；主要实现、复杂调试、长时间验证和并行模块交给 Terra。

信息不足不会自动升级成总体架构任务。总控应先检查或询问。只有真实的跨客户端/服务边界、未解决的共享契约、重大返工风险或高风险触发项，才进入总体架构阶段。

## 简明反馈

默认只给用户四行：

```text
已完成：<用户能理解的结果>
当前结果：<能否使用或验证>
阻塞：无 | <需要用户处理的唯一事项>
下一步：<一个最有价值的动作>
```

Base/Head、SHA、模型、审查编号和内部台账默认隐藏；只有用户主动询问，或它们能解释真实阻塞时才展示。

被总控验收的执行任务会收到一次结项回执：

```text
【总控结项回执｜非新任务，无需回复】
当前任务：<已接受的任务目标>
当前状态：已完成，等待下一步指令。
```

## 协调与批准提醒

- 一个工作区或可变范围只允许一个负责人。
- 独立模块可以并行，共享文件、迁移和共享契约必须串行。
- 派发成功不等于任务完成；总控必须读取终态报告并核验证据。
- 批准请求会立即通知用户：点名任务、说明动作、影响或风险，以及去哪里操作。总控看不到批准卡正文时会如实说明，不会猜测。
- 连续 30 分钟没有实质进展时，只允许一次只读快照和一次 Luna 状态询问；不创建 heartbeat、cron 或轮询。

## 配套 Skill 与能力发现

每个阶段最多选择一个真正需要的设计或探索类 Skill；普通工作不额外启用任何 Skill。

缺失能力查找已经内置，而且只读，不调用 `find-skills`。只有确实缺少专业验收方法时才搜索；搜索词会脱敏，候选内容按不可信信息处理，最多推荐三个。发现过程不会自动安装，也不会阻塞无关工作。

候选绑定、原子安装、失败回滚和崩溃恢复细节放在[安装安全参考](skills/project-lead/references/skill-installation-safety.md)中，只有用户批准精确候选后才读取。这样普通项目不会承受安装协议的上下文成本，同时保留原有安全边界。

## 安装

为 Codex 全局安装：

```bash
npx skills add yousef555khg-beep/project-lead@project-lead -g -a codex
```

开始总控对话时输入：

```text
使用 project-lead 管理这个项目。
```

## 配套 Skills

- 每个模式验收前使用 `verification-before-completion`。
- 只有标准和高风险审查节点使用 `requesting-code-review`。
- `prototype`、`codebase-design`、`apple-design`、`webapp-testing` 只在对应触发条件确实存在时使用。
